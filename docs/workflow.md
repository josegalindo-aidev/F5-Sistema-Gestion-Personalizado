# Workflow del equipo

## Kanban
Product Backlog → Ready → In Progress → Code Review → Testing → Done.

## Ramas
`feature/<issue>-<descripcion>`, `fix/...`, `test/...`, `docs/...`. Usar minúsculas, números y guiones.

## Pull Requests
Referenciar Issue, explicar cambio, incluir pruebas, documentar validación y solicitar revisión de otro integrante.

## Protección de main
Configurar PR obligatorio, al menos una aprobación, CI obligatorio y resolución de conversaciones antes de integrar (según permisos/plan de GitHub).

## Commits
Conventional Commits: `feat:`, `fix:`, `test:`, `docs:`, `refactor:`, `chore:`.
